# Implementation Plan: Phase 0 — The template exists

**Branch**: `000-phase-0-template-exists` (worktree `worktree-000-phase-0`) | **Date**: 2026-09-20 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/000-phase-0-template-exists/spec.md`, as
amended 2026-09-20 under constitution v1.1.0.

## Summary

Make `snackbyte-npm-base` a real template a package can be spun out of. The repo root
*is* a valid `ts`-mode package (so the template's own check gate proves the default
shape), a `variants/js/` overlay holds the `js`-mode files, and `scripts/init.mjs`
resolves a spin-out **out of tree**: it copies an explicit allowlist of product paths
into a target directory, substituting the package name, baking in `--source` and
`--cli`, and never touching the template checkout. Machinery tests spin out into a
temp directory in both modes and assert (a) the tree equals the allowlist, (b) no
placeholder survives, (c) `npm install && npm run check:all` is green, and (d) in `ts`
mode the build emits `dist/` with `.d.ts` and the export and `bin` run from it.

## Technical Context

**Language/Version**: Node 24 (`engines.node: ">=24"`), TypeScript 6 for the `ts` mode
and for the template's own source; the resolver is plain ESM JavaScript with no
dependencies so it runs before `npm install`.

**Primary Dependencies** (devDependencies only; the product has no runtime deps):
`typescript`, `vitest`, `eslint` + `@eslint/js` + `typescript-eslint` + `globals` +
`eslint-config-prettier`, `prettier`, `@types/node`. Versions match
`@snackbyte/spec-render` and `snackbyte-base` where they overlap.

**Storage**: N/A (files).

**Testing**: Vitest. Product: `tests/index.test.ts` (one passing stub). Template:
`tests/machinery/*.test.ts` (spin-out round-trips; not exported).

**Target Platform**: any machine with Node 24 and network access to the npm registry
(machinery tests run `npm install` in the spin-out).

**Project Type**: single project — a template repo whose root is a package, plus a
resolver script.

**Performance Goals**: N/A. Machinery tests are the slow part (two `npm install`s);
under two minutes total is the bar so the check gate stays usable.

**Constraints**: the resolver must run with zero dependencies; the product allowlist is
the only thing that crosses (constitution + spec FR-007); `ts` is the default and `js`
the explicit opt-out (FR-006); `--name` and `--repo` are required so no placeholder or
guessed owner can ship (a silently wrong `repository.url` is the exact class of
failure the house fail-loud rule exists for).

**Scale/Scope**: two graduates known (`spec-render`, `auth-client`); the template must
fit both without being built for either.

## Resolver contract (the one interface this phase exposes)

```
node scripts/init.mjs --name=<pkg> --repo=<git-url> --out=<dir> [--source=ts|js] [--cli] [--author=<text>] [--description=<text>]
```

- `--name` required; a bare name is scoped to `@snackbyte/<name>`; a scoped name is
  used verbatim. Becomes `package.json` name, the README title, and the `bin` key
  (unscoped part) when `--cli`.
- `--repo` required; the git URL for `repository.url` (`git+https://…​.git` form is
  normalised), `homepage` and `bugs` derived from it.
- `--out` required; must not exist or must be an empty directory. The resolver never
  writes anywhere else and never modifies the template checkout.
- `--source` defaults to `ts`; only `ts` or `js` accepted.
- `--cli` default off; with it `src/cli.*` and `bin` are included.
- `--author` defaults to the template `package.json`'s `author` (a fleet constant, not
  a guess); `--description` defaults to a stub derived from the name.
- Exit non-zero with the usage line on any violation; no partial output is left
  behind (write to a temp dir, then rename into `--out`).
